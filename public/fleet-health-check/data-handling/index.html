Fleet Health Check by NixonMade: data handling policy

Draft for legal review. This isn't legal advice and isn't yet a binding commitment.

1. Scope

This policy covers all client data that NixonMade receives while delivering a Fleet Health Check:

  • data collected through a client-created API client
  • files the client exports
  • reports and notes NixonMade produces from that data

2. Read-only access only

  • NixonMade asks only for read-only access. Clients create a dedicated API role with Read privileges only, using the published privilege list (api-permissions.md).
  • Our tooling enforces GET-only requests in code. The only exception is the standard OAuth token request.
  • We never ask for, accept, or use admin credentials. That covers Jamf Pro administrator accounts, local admin passwords, FileVault recovery keys, and the account that owns the push certificate. If any of these are sent to us by mistake, we delete them immediately, tell the client, and recommend rotating them.
  • The client keeps full control of access. We ask clients to disable or delete the API client as soon as collection is finished.

3. Credentials in transit

  • API client secrets are exchanged only through the channel agreed at intake, such as a password-manager share or encrypted message. They are never sent by plain email or chat.
  • Secrets are held only in memory or environment variables while the collection runs. They are never written to disk, logs or reports.

4. Data minimisation

  • We collect only what the checks need. That means inventory status fields, policy, group and profile configuration, extension attribute and script contents, and certificate expiry dates.
  • Reports show secret-like values found in scripts as "value redacted". We never reproduce them.
  • Clients may withhold any section (for example scripts). The report will then list the affected checks as "not evaluated".

5. Storage and encryption

  • Client data and reports are stored encrypted at rest: an encrypted volume or container on a FileVault-encrypted, managed work device, with access limited to NixonMade personnel delivering the engagement.
  • No client data is uploaded to third-party AI services, public repositories, or shared drives without the client's written consent.
  • Reports are delivered through the agreed secure channel.

6. Retention and deletion

  • All raw client data (API output and exported files) and working copies are deleted within 30 days of report delivery, or sooner on request.
  • If the client requests it, the final report may be kept for up to 30 days to answer follow-up questions. It is deleted on the same schedule unless the client asks in writing for it to be kept longer.
  • Deletion confirmation: once data has been deleted, NixonMade sends the client written confirmation listing what was deleted and when.

7. Confidentiality and NDA

  • All client data and reports are treated as confidential.
  • A mutual NDA is available on request, and can be signed before any access is granted.
  • No client is named, and no client data, screenshots or findings are used in marketing, without explicit written permission. Sample reports use fabricated data only.

8. Incidents

If NixonMade becomes aware of unauthorised access to client data, we will notify the client without undue delay and include what is known. We will help with the client's own incident process, including rotating any credentials involved.
