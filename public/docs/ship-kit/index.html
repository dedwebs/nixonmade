Requirements

  • A Mac, with Xcode, because the scripts run xcodebuild
  • An Apple Developer account
  • A SwiftUI iOS app. Apps with extensions are supported.
  • An XcodeGen project. The drift check compares the committed project with xcodegen output.
  • Apple's latest Program License Agreement, accepted. Preflight reports PLA_NOT_ACCEPTED until you accept it.
  • For cloud signing, an App Store Connect API key with the Admin role. Otherwise, sign in to Xcode.
  • Cursor or Claude Code if you use the included skills. The runbook is for an agent that can run shell commands.

Walkthrough

A dry run on the sample app ShipKitDryRun ran the drift check, the Mac gate, a build-number bump with --dry-run, and the archive. That dry run did not run export or upload.

  1. Commit the project before the drift check. The check looks at the committed .xcodeproj.
  2. Run the drift check. 
    $ scripts/check-pbxproj-drift.sh
    On the sample app it printed that the committed project matches xcodegen output.
  3. Run the Mac gate before the bump. Pass the commit you just recorded. 
    $ scripts/mac-gate.sh <commit>
    On the sample dry run the gate picked a simulator, ran a Release build and the tests with CODE_SIGNING_ALLOWED=NO, and printed GATE PASS.
  4. Read the maximum build number live. Do this after the gate and before the bump.
  5. Bump only after the gate has passed. Use dry-run first. 
    $ scripts/bump-build.sh <number> --dry-run
    On the sample app, dry-run reported that it would set CURRENT_PROJECT_VERSION in project.yml and then run xcodegen generate. Dry-run does not apply that change.
  6. Archive the same commit the gate passed. 
    $ scripts/archive.sh <commit>
    The sample dry run wrote build/archives/ShipKitDryRun-1.xcarchive.
  7. Export with the export and TestFlight upload script. The archive transcript names export-upload.sh. The sample dry run did not run it.

Configuration

  • The bump script changes CURRENT_PROJECT_VERSION in project.yml, then runs xcodegen. Use --dry-run to see the change without writing it.
  • The sample archive invocation passed DEVELOPMENT_TEAM and PRODUCT_BUNDLE_IDENTIFIER to xcodebuild.
  • The kit includes ship.env and ExportOptions.plist templates.
  • Cloud signing needs an App Store Connect API key with the Admin role. If the key is not Admin, sign in to Xcode instead.
  • The scripts read keys from your own environment. The kit does not send those keys to NixonMade.

FAQ

Which apps does it cover?
SwiftUI iOS apps, including apps with extensions.
What order do the scripts run in?
Commit, then the drift check. The gate runs before the bump. Read the maximum build number live before you bump. Archive after that. Export is a separate script and was not part of the sample dry run.
Does the kit submit to App Store review?
No. App Store submission is outside this kit.
What do updates cover?
Updates cover 1.0.x. A later major version is not included.
Who is the licence for?
One developer. No resale. See the terms.

Troubleshooting

  • Commit before the drift check. The check compares the committed project with xcodegen output. On the sample app, success was the line that the committed project matches xcodegen output.
  • Do not bump before the gate passes.
  • If preflight reports PLA_NOT_ACCEPTED, accept Apple's latest Program License Agreement, then run the preflight again.
  • If cloud signing fails because the App Store Connect key is not Admin, sign in to Xcode instead.

The kit also includes TROUBLESHOOTING and the checklists for the Mac gate, the QA gate, the archive smoke test, and upload.
